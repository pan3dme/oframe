# 看门狗加固交付说明

日期：2026-11-20。原始文件保存在 `backups/watchdog_20261120/`。

## 已实现

- IWDG 在 `main()` 最开始启动，不依赖 HAL tick，覆盖 HAL、时钟和外设初始化。保持约十秒典型超时，按 60 kHz LSI 最短约 6.66 秒。
- 喂狗统一经过 `Safety_Feed()`：tick 未推进就不重复喂狗；启动、时钟、收发、搜星、连续等待、Flash、ADC 各阶段有期限和阶段编号。
- 连续定位等待下一轮时补齐喂狗。TX/RX 五秒未完成立即记录原因并复位，不再额外空等三秒。
- STOP 改为最多三个 RTC 秒一段；入睡前喂狗，每段必须看到 RTC 到达目标才允许再次喂狗。伪唤醒不喂狗。
- 清 RTC/EXTI17 挂起标志，暂停 SysTick，先清旧事件再设闹钟，使用原先实测可用的 `WFE + EXTI17、ALRIE=0` 唤醒方式。返回前修正 HSI 下的 SysTick。
- RTC 等待超时明确失败；高、低、高读取避免半字进位竞态。每次 MCU 重启重建 RTC 并确认计数推进；RTC 故障或 STOP/RTC 阶段 IWDG 复位后，下一次启动优先用 LSI。
- HSE 无法起振时尝试 HSI/PLL 64 MHz，正常情况下仍使用 HSE/PLL 72 MHz。USART/SPI/ADC 初始化和 STOP 后恢复按实际时钟进行。
- NMI、HardFault、MemManage、BusFault、UsageFault、初始化错误统一记录并复位，故障路径不打印、不等待 tick。
- 使用 BKP DR1～DR5 记录原因、阶段、连续失败次数和 RTC 降级标志，无 Flash 喂狗日志磨损。备份域重建时恢复这些诊断数据。
- 连续三次故障后，启动退避 30/60/120/240 秒，之后最多 600 秒。有效对时或发给本机的已识别指令清连续失败计数；正常远程重启不增加次数。
- 链路健康使用单调 RTC 累计；未对时也监控，夜间非工作时间不计入两小时阈值，低电量跳过上报和连续定位期间暂停累计。无效帧不刷新健康。首个两小时请求射频重初始化，再过两小时仍无有效交互则整机复位。
- 时间换算使用 64 位中间量，移除旧版约 6.9 天乘法溢出和约 11 天补偿失效的边界。
- ADC 校准/转换超时会复位；采样后关闭 ADON，PA0 配为模拟输入，避免持续开启和数字输入漏电。PB15 在切为输出前预置关电电平。

## 配置保存

- 设备名、配置、功率、中心坐标、设备数量、搜星上限仍使用原来的六个页地址，原 MAGIC 和 `page + 4` 数据布局兼容。
- 每个新记录增加身份/长度/数据 CRC 和最后提交标记。旧版记录只在页脚完全为空且数据通过原有范围/格式校验时加载。
- 最后一页 `0x0800FC00` 用作恢复日志页，原项目没有使用此页。
- 更新顺序：先完成上一笔恢复 → 新值写日志并校验/提交 → 改写目标页并校验/提交。日志提交后掉电，启动按日志恢复。日志未提交就掉电，目标页仍保留旧值。
- 保存相同配置不重复擦写。擦写返回值和写后回读均检查，失败不发送“成功保存”的确认后继续运行，而是进入故障复位。
- 链接区限制为 `0x08000000～0x0800E3FF`，保留整个 `0x0800E400～0x0800FFFF` 配置/日志区域。
- 新存储只能保证新版本执行的事务；历史固件已经写坏的旧配置无法补出完整数据，仍需依赖范围校验/默认值。

## 射频驱动与协议

- 将参与编译的驱动和头文件固定到本项目 `Radio/`，没有修改外部 `../Common/RadioF103/`，其他项目不受这次改动影响。
- 收发 ISR 共享标志加 volatile；SPI 使用与 tick 无关的有界轮询，单个 CS 事务保护中断状态，SPI 错误记录后复位。
- 上报类型、字段数量、时隙、GPS 搜星/连续上报规则保持原有逻辑。精简部分重复串口日志，GPS 状态仍显示定位、坐标、卫星、耗时、接收字节数和 RTC。
- 原类型 8 重启帧仍为 `8|设备|rst:原因|计数|`。原因字符串增加阶段后缀，例如 `8|v3-0|rst:IWDG-10|2|`，表示上次在 STOP 阶段超时。云端若对原因做精确字符串匹配，需接受这个后缀。

| 阶段编号 | 含义 |
| --- | --- |
| 1 | 早期启动 |
| 2 | 系统时钟 |
| 3 | RTC 初始化 |
| 4 | 主循环/普通处理 |
| 5 | 射频初始化 |
| 6 | 发射 |
| 7 | 接收 |
| 8 | 搜星 |
| 9 | 连续定位等待 |
| 10 | STOP 分段 |
| 11 | 配置 Flash |
| 12 | ADC |

原因包括 POR、PIN、IWDG、INIT、RTC、TX、RX、SPI、RF、LINK、FLASH、ADC、NMI、HARD、MEM、BUS、USAGE、REMOTE、LIMIT。BKP 诊断不承诺跨完全断电保存。

## 构建与检查

在工程根目录执行：

```powershell
node tools/build_watchdog.cjs
node tools/test_watchdog.cjs
```

构建脚本使用 `D:/Keil_v5/ARM/ARM_Compiler_5.06u7/bin`；可通过 `ARMCC5_BIN` 指定其他安装目录。脚本读取实际 uVision 工程文件列表，完整编译、链接并生成 HEX/BIN，不连接或烧录设备。

- 完整构建通过，0 编译警告，链接成功。Code=30560，RO-data=1856，RW-data=324，ZI-data=4356 字节。
- 处于 Keil Lite 32 KiB 限制之内，但余量很小；后续新增功能应重新检查镜像大小。
- HEX 校验和、初始 SRAM 栈指针、Thumb 复位入口与所有编程地址检查通过；最高数据地址 `0x08007EFF`，不包含配置/日志页。
- 10444 项自动检查通过。包含从源码函数体机械转换执行的喂狗、工作时段累计、半年漂移/RTC 回绕检查，以及配置事务掉电模型和 HEX 检查。
- 掉电模型覆盖 1119 个保存边界、564 个恢复边界，各运行写入前中断和半字部分擦写两种模式，并检查 CRC 对逐位损坏的检测、恢复后再保存其他配置。
- **掉电模型没有执行 MCU 上的实际 C Flash 驱动，不能替代硬件故障注入。** 本机 FVP CPU 模拟器缺少许可，没有据此宣称整机仿真通过。
- 链接器静态栈分析为 712 字节加递归/间接调用未知量，配置栈为 2048 字节；它不代替上板栈水位测试。

输出目录：`MDK-ARM/watchdog_build/`，包含 `STM32_ONLY_SEND.hex`、`.bin`、`.axf`、`.map`、调用图、`build.log` 和 `test_results.json`。

## 烧录与上板验收

本轮没有烧录设备。保留现有设备配置时，应使用仅擦除程序所占扇区的烧录设置；全片擦除仍会擦掉配置和日志。

建议先在一块测试板上验证：

1. 普通上报和类型 1 GPS 上报的时间点、收发窗口、原有指令及回包。
2. 连续定位提前成功、始终无定位、满 60 分钟、设置 1/4/10 分钟搜星上限。
3. 多轮 STOP 真正进入低电流，伪唤醒后能再次睡眠；LSE/LSI 两种来源均测量，验证最低看门狗余量。
4. 屏蔽 TX/RX IRQ、暂停 tick、前台/中断卡死和强制异常后的复位时间与 `rst:` 上报。
5. LSE/HSE 起振失败和运行中失效的降级与恢复，尤其核对本批芯片的 WFE 行为。
6. 配置写入和启动恢复过程中实际切电，检查旧/新配置及 CRC；检查烧录工具不会误擦配置区。
7. 中继离线、跨夜、低电恢复、连续失败退避，以及真实休眠/搜星/发射电流和温度影响。

GPS PA3 复位脚的接线未经确认，本轮没有新增驱动动作。LoRa 独立电源开关也未发现，故其恢复依靠 RST 和 MCU 复位；如果某种模块故障必须断电，仍需硬件支持。

半年可靠性和续航需要电池容量、实际功耗、高低温/供电测试共同验证，不能由这次软件修改直接保证。
