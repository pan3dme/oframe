# ONLY SEND 看门狗与低功耗加固

日期：2026-11-23。目标：正常进入 STOP 低功耗，异常允许直接重启，连续故障时尽量降低等待期间的耗电。本次没有连接、烧录或操作设备。

## 已完成的修改

### RTC 停走后可以重启

`Safety_CheckRtc()` 用清醒期间的 HAL tick 检查 RTC 是否推进，连续 3000 ms 未看到变化就记录 RTC 故障并复位。检查放在 RTC 读取出口；主循环重复设置阶段期限不会重置这个独立监控。

STOP 期间 HAL tick 暂停，允许 RTC 正常推进；RTC 不唤醒时由持续运行的 IWDG 兜底。已有的“tick 冻结时不能持续喂狗”、各阶段期限和异常处理保留。

这是停止推进检测，不是 RTC 精度校准，也不能识别所有错误跳变。3000 ms 是监控期限；实际触发时刻还取决于下次执行 RTC 读取。

### 射频访问和休眠准备

- 保护“选页 + 访问”和读改写的整个过程，保存并恢复调用者原来的中断屏蔽状态，兼容嵌套 CS 事务及中断上下文。
- 初始化射频时临时禁止其 EXTI 中断，完成后清理挂起状态并重新使能。
- 深睡准备中的可读模式寄存器写入，最多回读重试三次；失败可重新执行一次完整准备，两次准备都失败则向应用返回失败。
- 保留已有双次深睡指令顺序。首次准备成功后的第二遍不回读验证，避免将已深睡、不再响应读取的模块误判为失败。
- 应用统一通过 `loraSleep()` 处理休眠失败，正常业务路径失败就记录 RF 故障并重启。已休眠或启动时保持复位的模块不重复执行验证写入。
- 为 MAPM 接收索引增加边界保护，避免异常状态写坏内存。

**最终深睡命令没有可靠的软件回读确认，不能把 SPI 成功当成整板低电流证明。** 保留第二遍指令用于降低最后一次写入丢失的风险，仍须上板测量。

### STOP 与故障退避

- 保留当前项目使用的 WFE/EXTI17/ALRIE=0 唤醒方式、最多三个 RTC 秒分段，以及到达 RTC 目标才允许后续喂狗的规则。
- 休眠期间保存并屏蔽 LoRa、GPS 的 NVIC 中断，减少外设毛刺导致的无效唤醒；结束后恢复原使能状态。
- STOP 入口清唤醒标志；修正备用 RTC Alarm 中断函数名，使其与启动向量一致。
- 连续三次故障后的 30/60/120/240 秒、最高 600 秒退避保留。进入退避前尝试初始化射频并让它深睡；初始化或准备失败时保持 LoRa 复位脚为低，随后仍执行退避。
- 启动 GPIO 阶段就保持 LoRa 复位有效，防止上一次运行遗留的活动状态继续运行到正式初始化。
- 故障重启跳过首次 STOP 前十秒烧录等待；正常启动保留该等待。
- 固件版本标记变化不再清除连续故障次数。仍由有效协议交互清除。
- 最新电量策略：低于 30% 只限制 GPS，普通 LoRa 上报、接收窗口及链路监控保持运行；不再使用 100 次上报豁免规则。自动 GPS 时间窗内改发普通时间/电量帧，低电量的单次/连续 upgps 请求跳过并清除，不排队到充电后再自动执行。电量恢复至 30% 及以上后，按原有时段/新指令允许 GPS。

保持复位主要用于抑制模块活动，**复位状态的实际电流需要测量，不能等同于独立断电**。时钟/RTC 等在退避入口之前发生的持续故障，以及底层 SPI 直接触发的复位，仍可能到不了退避阶段。

### GPS 运行期间的电量变化

按最新要求，取消搜星和连续定位期间的十秒电量复查。保留普通唤醒/上报前的电量采样，以及 GPS 任务启动前的 30% 门槛；任务开始后按原有定位成功、搜星超时或连续定位期限结束，不在任务中追加 ADC 电量采样，也不因定时复查中断任务。

### 时钟、存储和构建

- STOP 后配置系统时钟时，重新配置已经启用的 USART1/USART3，并终止、重新武装 GPS 接收，适配 HSE/PLL 72 MHz 与 HSI/PLL 64 MHz 之间的变化。
- uVision 和构建脚本使用的链接区统一截止到 `0x0800DFFF`，为 `0x0800E000` 开始的七个配置/版本页和 `0x0800FC00` 日志页保留空间。
- 现有配置地址和事务布局保持兼容；对外版本号 `DEMO_VER` 为 `V2.2`，内部升级标记 `APP_VERSION` 为 11。
- 构建清单增加相关头文件、构建和验证脚本的哈希。验证脚本检查当前源码与 HEX/BIN/AXF 的一致性，拒绝用旧固件充当当前源码的验证结果。
- 精简重复串口日志，发送日志统一为 `[TX]`；保留故障、接收和 GPS 搜星状态信息，为 Keil Lite 的镜像限制留出空间。

## 上板验收重点

1. 独立供电、脱离调试连接，测量多轮 STOP 的最低及平均电流；确认三秒分段只是短暂处理 RTC/喂狗，没有每段重启射频或搜星。
2. 普通上报、GPS 自动上报、连续定位、所有现有配置指令都能完成；检查唤醒后的 GPS 9600 波特率和调试串口。
3. 清醒等待发送时停止 RTC、STOP 时停止 RTC/屏蔽唤醒、冻结 tick、前台死循环和中断卡死：分别观察复位原因、恢复上报及重新入睡。
4. 屏蔽射频完成 IRQ、制造模式回读失败、断开模块：检查有界重试、故障复位，以及连续故障后的退避。实测 LoRa 保持复位时的电流。
5. 低电压和充电恢复、HSE/LSE 故障及高低温条件：确认不会出现持续高功耗重启循环。
6. 配置/版本保存及恢复时实际切电，验证旧/新完整记录和恢复后继续保存。

GPS 电源控制是否实际断电、LoRa 是否存在必须断电才恢复的故障、整板待机电流和电池寿命，都需实板确认。本次软件加固不能保证任何硬件故障都可恢复。

## 普通时隙调度更新

普通定时上报改为选取当前时间之后、满足最短间隔的最近本机时隙，包含当前周期尚未到达的时隙；不再只因剩余等待小于半周期而盲目跳过。最短间隔仍为当前有效普通周期的一半，但只以最近一次完成发送的定时时间帧（类型 2）或定时 GPS 帧（类型 1）的单调 RTC 时刻为起点。对时只改时间基准，不改这个起点；配置、信息、中心坐标回包和 UPGPS 类型 5 不更新它。不同周期与跨午夜按每天零点重新划分时隙。

UPGPS 的 gpsRunContinuous/gpsWaitForFix/gpsSearchAndReport 函数体与本轮修改前逐字节一致。原 HAL tick 的任务计时、轮次间隔和无定位延长规则保持不变；没有增加电量复查。回归验证在连续任务中反复注入前后跳变的时间校准及普通调度重算，任务上报轨迹和结束时间与不注入时一致。保留之前的低电量启动门槛和看门狗异常复位。

原有 `[FAST]` 独立调试行省去，`[SCHED] next=... wait=...` 继续显示实际下次上报点及剩余等待。对外版本号仍为 V2.2。修改前备份位于 `backups/slot_schedule_20261123/`；尚未烧录或上板验证。新增时隙回归覆盖 1～60 分钟周期、多个设备索引/台数、跨午夜、重复重算、正反对时及 RTC 回绕。
