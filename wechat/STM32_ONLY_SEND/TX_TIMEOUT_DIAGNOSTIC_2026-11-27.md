# SEND 2000ms 强制 RX 测试告警

版本：V2.11，APP_VERSION=22。日期：2026-11-27。

需要接收窗口的普通上报（类型2）和定时 GPS 上报（类型1），如果发起发送后
2000ms 仍没有软件发送完成标志，就记录本次上报计数并执行已有的强制 RX 流程。
正常收到发送完成 IRQ 时不记录、不补发告警。

当前接收窗口最多5000ms，从配置接收时计时；收到一条完整帧后可提前结束。
CRC错误只使用原窗口剩余时间重启接收，不另加5秒。软件丢失接收 IRQ 的保护期限
为6000ms，RX阶段看门狗期限为7000ms。相关源码注释、函数名和日志均已同步为5秒。
CRC日志在错误发生后重新计算剩余预算，避免显示等待前的旧值。

接收窗口结束并返回后，在现有 reportPendingMessages 流程中先延时1000ms，
再补发一条类型8测试告警，排在原有启动原因和配置等回包之前：

```text
8|设备名|TXTO|2000,原上报计数|告警包计数|
8|v3-14|TXTO|2000,4|5|
```

- `TXTO`：等待发送完成超时并强制转 RX 的诊断标识。
- `2000`：触发阈值，单位毫秒；不是测得的实际空中发送时长。
- `4`：触发强制 RX 的上报包计数，补发前保留原值。
- `5`：本次告警使用既有 txCountNext 分配的新计数，999后回绕到1。

TX_COUNT_ENABLE=0 时省略末尾告警包计数字段，原上报内部计数仍保留。
成功收到下行和正常接收超时都会继续补发；CRC错误后的窗口内重试不触发提前补发。
告警本身使用辅助上报流程，不开接收窗口，也不会递归生成强制 RX 告警。
补发函数正常完成后清除待发标记，后续普通窗口不会重复发送。

记录仅保存在 RAM，不写 Flash。若接收期间故障复位、执行远程重启或告警发送失败导致
重启，未发出的记录不跨复位保留。告警发送完成也不等于 CENTEN 或云端确认收到。
CENTEN 当前源码已将类型8按既有信息上报转发到 DTU，无须修改其报文分类。
