# SEND 休眠功耗与 GPIO 检查

检查日期：2026-11-28。范围：当前 STM32_ONLY_SEND 源码、项目内电路截图和现有测试脚本。本次未修改固件、未烧录、未连接电流仪器。电路截图与代码存在接线差异，结论以明确的条件区分；不能由代码推出实际休眠电流。

## 结论

当前实现了低功耗稳压器 STOP、关闭 ADC、GPS 电源控制和 LoRa 深睡准备，但 GPIO 尚未形成完整的休眠配置，不能认定已经达到最低功耗，也不能保证不存在引脚引起的额外耗电。

优先排查 GPS 断电后的接口电平，以及未使用引脚的浮空输入。PA3 的反向供电风险取决于实物是否已接到 GPS RESET_N；项目内截图显示 PA3 未连接，头文件也写着复位接线待完成，不能把这个条件性风险当成已发生的漏电。

## 已有措施

- `Core/Src/main.c:1803` 设置 LPDS、清除 PDDS，并配合 SLEEPDEEP/WFE 进入 STOP，采用低功耗稳压器。
- `Core/Src/main.c:1781` 起屏蔽 LoRa EXTI2、GPS USART3 中断并停止 SysTick，结束后恢复。
- `Core/Src/main.c:3476` 将 PA0 配置为模拟输入；初始化和电量采样后均清除 ADC ADON，见 3510、3556 行。
- `Core/Src/main.c:3663` GPS 关闭时 PB15 输出高，PB1 输出低。是否真正切断 GPS 电源需要核对实物开关电路并测量。
- `Radio/src/pan3029_rf.c:702` 起关闭天线开关、TCXO，执行逐级深睡命令；`Core/Src/main.c:1466` 对准备失败进行复位恢复。最后的深睡指令无法据此证明模块已处于目标电流。

STOP 不自动把 GPIO 变为高阻或模拟输入。本项目自带 ST HAL 在 `Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_pwr.c:254` 明确说明，STOP 中 I/O 保持运行时状态。不能用“CPU 已经睡眠”推断“接口已经不耗电”。

## 逐项发现

### 1. PA3：GPS 断电后仍推挽输出高，存在有条件的反向供电风险

证据：`Core/Src/main.c:3391-3396` 配置 GPS_RST 为推挽输出并拉高；`gpsPowerOff()` 的 3661-3676 行只控制 PB15、PB1 和软件状态，没有释放 PA3。`Core/Inc/main.h:87-93` 把 PA3 定义为 L76K RESET_N。

如果 PA3 已直连 GPS RESET_N，且模块该接口在主电源关闭时不允许外部高电平，MCU 可能通过接口保护或内部电路给模块反向供电。实际电流取决于模块接口结构、备用供电及板上隔离，不能只凭源码量化。

如果 PA3 仍未连接，则此处没有通向 GPS 的反向供电路径，但保留这个无用输出没有必要。

建议：先确认接线和模块掉电接口要求。采用模块允许的开漏释放/隔离或掉电前高阻策略；如果使用上拉，应核对其供电域，避免从常供电的 MCU 电源持续上拉已断电模块。不能只把“高电平”替换成一个未经硬件确认的固定电平。

### 2. PB11：GPS 断电后仍是无上下拉数字输入

证据：`Core/Src/stm32f1xx_hal_msp.c:143-146` 配置 PB11 为 GPIO_MODE_INPUT、GPIO_NOPULL。GPS 关闭函数没有改 GPIO；STOP 入口仅屏蔽 NVIC，没有关闭输入缓冲或终止 UART 接收。

若断电后的 GPS TX 为高阻，PB11 没有明确的外部电平约束，存在浮空和额外输入缓冲电流风险。屏蔽中断只控制 CPU 是否处理事件，不能消除这个电气问题。

建议：GPS 关闭后将 PB11 设为模拟输入；重新上电时先恢复 UART 输入配置、清理接收状态并重新武装接收。策略最好跟随 GPS 开关，而非仅包在 STOP 入口，因为 GPS 关闭后 MCU 仍有运行阶段。

PB10 在 MSP 中仍被配置为 USART3 TX 的复用推挽，但 `Core/Src/main.c:3338` 实际使用 UART_MODE_RX。因此不能直接断言 PB10 正在持续输出高电平。应按未使用信号处理，并确认它与 GPS RX 的实际连接和掉电行为。

### 3. 未使用 GPIO 未统一配置为模拟输入

证据：`MX_GPIO_Init()` 只配置 GPS 和 LoRa 信号；全项目应用代码中没有对其余引脚执行统一模拟输入配置。自带 ST HAL 的 `stm32f1xx_hal_gpio.c:36-38` 说明复位后多数 GPIO 为浮空输入。

PA4、PA8、PA11/PA12、PB12/PB13/PB14、PC13 等可作为候选，但必须逐个核对实物。PB2/BOOT1、晶振引脚及 SWD 引脚需要单独考虑，不应直接对所有 GPIO 批量覆盖。

建议：建立明确的未用脚掩码，把确认未连接且不承担特殊功能的引脚设置为 GPIO_MODE_ANALOG、GPIO_NOPULL。PA13/PA14 当前保留 SWD；不要为省电直接破坏现有下载方式。

### 4. PA2：LoRa IRQ 下拉存在条件性的电阻耗电

证据：`Core/Src/main.c:3430-3433` 将 PA2 配置为上升沿 EXTI 和内部下拉；STOP 中不修改该电阻。

如果 PAN3029 深睡后 IRQ 为低，则没有高电平对内部下拉形成的这条持续电流路径。如果 IRQ 仍保持高，则有持续电流经过内部下拉。应测量睡眠期间 PA2 的实际电平，不能直接断言它一定漏电。

建议：若休眠不依赖该脚唤醒，可评估只在 STOP 期间将其设为模拟输入，返回后恢复 EXTI 和既有中断清理顺序；运行阶段的下拉是否保留要结合模块 IRQ 输出特性决定。

### 5. LoRa SPI 与调试串口没有单独的休眠电气配置

PA5/PA6/PA7 在 GPIO 和 SPI MSP 初始化中一起设置为复用推挽。PA6 是 MISO，应按 STM32F1 SPI 主机输入的要求单独复核；不要仅因三脚同配就认定已经发生推挽冲突。LoRa CS 无效时，其 MISO 如果高阻，MCU 输入电平也需要考虑。

建议：睡眠期间评估 PA6 模拟输入；工作时单独配置正确的 MISO 输入模式。SCK/MOSI 若需要固定电平，应结合 SPI 空闲极性和模块要求，PB0/CS、PA1/RESET 则必须保持确定且合适的控制状态，不能一并浮空。

PA9/PA10 是 USART1 调试接口，当前 PA10 为无上下拉输入。调试器或 USB 串口适配器未接时需评估浮空；适配器掉电而 PA9 仍驱动时需评估反向供电。测量整板功耗时应脱离这些外部连接。

### 6. 三秒唤醒喂狗会增加平均电流，属于已有可靠性取舍

证据：`Core/Src/main.c:1471` 的 WDG_SEG_SEC 为 3；STOP 循环按最多三个 RTC 秒分段唤醒，`Core/Src/reliability.c:117-129` 处理 IWDG 喂狗与阶段更新。IWDG 在启动时即开启。

因此长休眠中存在周期性 CPU 活动，整段平均电流会高于稳定 STOP 平台电流。它是 RTC 停走/唤醒失效时的恢复保障，不建议直接取消。也不应未经重新设计就把 STOP 替换为会改变上下文保持和启动流程的 STANDBY。

## 电阻常耗与 GPIO 漏电要分开

项目 `mcu.png` 的 PA0 分压画为 100kΩ + 100kΩ，顶端标为 +3.3V。若实物与该图一致，电阻支路电流约为 3.3V / 200kΩ = 16.5µA，即使 MCU 已睡眠且 ADC 已关闭也仍存在。

代码注释则称分压接电池；如果实物确实接电池，4.2V 时电阻支路为 21µA。这是电路固定消耗，不能归咎于 PA0 漏电。截图、代码注释与实物的连接需核对后才能作整板预算。

## 验证情况与限制

实际运行 `node tools/test_low_power.cjs`，在第 59 行断言失败：脚本要求 TX_RX_FALLBACK_MS 等于 2000ms，而当前 `Core/Src/main.c:53` 为 1500ms。测试提前终止，本次不能报告整套低功耗回归通过，也没有为使测试通过修改业务参数或测试预期。

对比现有 `MDK-ARM/watchdog_build/build_manifest.json`：当前 main.c 哈希与清单不一致；本次核对的 MSP、reliability.c、main.h、pan3029_rf.c 则一致。既有二进制构建记录不能完整代表当前源码，更不能证明设备里烧录的版本。

本检查的芯片行为依据包含项目自带 ST HAL 源码。在线厂商资料检索未返回可核对内容，未引用未经核实的模块掉电接口规格，也未给出 MCU 或整板的保证电流。

## 建议上板测量

1. 脱离 ST-Link、USB 串口及可能提供电源的外部连线，正常启动第一次十秒下载窗口结束后，观察多轮休眠。
2. 同时记录稳定 STOP 平台电流、三秒唤醒脉冲和整段平均值，避免只读最低瞬时值。
3. GPS 关闭时测量 GPS_VCC 是否按设计下降；若仍有电压，用接口隔离前后的电流差验证是否为反向供电。高阻表读到残压本身不能证明有显著供电能力。
4. PA3 若已连接，优先比较释放 PA3 前后的 GPS 电源残压和整板电流；同时核对 PB10、PB11 和 PB1。
5. 测量睡眠期间 PA2 电平，验证内部下拉是否形成持续负载；再比较未用脚模拟输入、GPS RX 模拟输入前后的电流。
6. 每次 GPIO 改动后验证 GPS 首次定位/再次上电、LoRa 收发及 RTC 唤醒，避免只降低电流却破坏恢复功能。

在完成 GPIO 优化和实板测量前，准确结论是“已有深度休眠，但仍存在未处理的额外耗电风险”，而不是“已经最低功耗”或“已证实 MCU 引脚没有漏电”。
